Aufgabe 1: Breitensuche auf einer Hoehenkarte
============================================================
a) Modellierung
- Knoten: jedes Feld (Zeile, Spalte)
- Kante A->B: B ist Nachbar von A und Hoehenregel ist erfuellt
- Wahl: Adjazenzliste statt Adjazenzmatrix
  Grund: Das Gitter ist ein duenn besetzter Graph (max. 4 Ausgaenge pro Knoten),
  daher ist der Speicherbedarf mit Liste deutlich geringer als O(|V|^2).

b) Kuerzester Pfad S -> E (Beispielkarte)
- |V| = 40, |E| = 111, |V|+|E| = 151
- Pfadlaenge (Anzahl Schritte): 31
- Pfad: (0,0) -> (1,0) -> (1,1) -> (2,1) -> (3,1) -> (3,2) -> (4,2) -> (4,3) -> (4,4) -> (4,5) -> (4,6) -> (4,7) -> (3,7) -> (2,7) -> (1,7) -> (0,7) -> (0,6) -> (0,5) -> (0,4) -> (0,3) -> (1,3) -> (2,3) -> (3,3) -> (3,4) -> (3,5) -> (3,6) -> (2,6) -> (1,6) -> (1,5) -> (1,4) -> (2,4) -> (2,5)

c) Laufzeitvergleich und O(|V|+|E|)-Plausibilitaet
- Beispielkarte: avg BFS = 0.061981 ms, |V|+|E| = 151
- Echtdaten: avg BFS = 0.060880 ms, |V|+|E| = 151
- Echtdaten: Kuerzeste Pfadlaenge S->E = 31
- Laufzeitverhaeltnis (echt/beispiel): 0.982236
- Verhaeltnis (|V|+|E|) echt/beispiel: 1.000000
- Relative Abweichung: 1.78%
- Bewertung: Messung ist grob konsistent mit linearem Wachstum.

d) Optional: Kuerzester Pfad von beliebigem 'a' (oder S) nach E
- Beispielkarte: kuerzeste Distanz = 29 ab Start (4, 0)
- Echtdaten: kuerzeste Distanz = 29 ab Start (4, 0)
